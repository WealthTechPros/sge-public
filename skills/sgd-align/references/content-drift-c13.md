# C13 — Spec ↔ Code content-drift mechanism

Full mechanism for the **C13** cascade check referenced from `SKILL.md` Step 1. Read this
before running or interpreting C13.

**C13 — Spec ↔ Code content-drift check.** Every other check verifies *presence* (a link exists) or compares recorded metadata (C9's schema/version/hash comparison); this is the only check that reads the *behavioural content* on both sides of a spec↔code link — stated scenarios vs. actual implementation — and judges whether they still agree.

**Eligibility (deterministic, bounded — never "read the whole codebase every sweep").** A spec is eligible iff **both** hold:
1. Its status is `approved` or `implemented` (per this repo's status convention, Step 0).
2. Its body cites **at least one path token that resolves to an existing file or directory in the repo at the audited SHA**. Collect candidate tokens mechanically: any path-shaped string (contains `/` or a source-file extension) in the spec's body — an `**Extends:**` / `**Implementation:**` / "Files" line, inline code spans, wherever — then test each against the working tree. **Existence on disk is the whole test.** A token citing another spec, an issue number, or a module *name* that isn't a real path (e.g. SPEC-056-style "Extends: SPEC-055") simply fails the test and contributes nothing — no convention interpretation, no guessing. The eligible set is exactly the specs with ≥1 surviving path.

A spec with no surviving path is **skipped, not flagged** — there is nothing to diff against, and a genuinely-implemented spec with no code linkage is C6's finding (orphan spec), not this check's. (The L5 DAG Manifest stays out of scope per the sweep-scope table above — this check reads only the spec files themselves, not platform-side DAG state.)

**Mechanism (capped fan-out):** dispatch one read-only subagent per eligible spec, **at most 8 concurrently** (mirroring the ~8 cap fleet mode uses for its per-repo agents — two independent limits that happen to share a value); queue the rest. If the eligible set exceeds **`--max` × 2** specs, check the highest-severity-first slice up to that cap and report the deferred count in the summary — bounded coverage, never a silent cap (see Safety). Each subagent reads the spec's full stated behaviour — every Gherkin scenario and acceptance criterion, not just front-matter — and its surviving cited path(s), then judges: does the code still do what the spec states, or has it materially diverged? A pass or a gap, nothing in between — with one guardrail: if **none** of the surviving paths is plausibly the implementation the spec governs (e.g. an ADR or doc cited only for precedent/context), the subagent reports that spec **skipped** — same outcome as ineligible, counted in the summary's skip note — rather than judging drift against a file that never implemented it. The eligibility test stays purely mechanical; this plausibility call lives inside the per-spec judgment the subagent is already making.

**On drift found:** emit a `gaps[]` record in the **exact same contract shape** as every other check — `{ "check": "C13", "layer": "L3↔spine", "key": "C13:<SPEC-NNN>", "artefact": "<SPEC-NNN> (<path>)", "expected": "<the spec's stated behaviour, quoted>", "found": "<what the code actually does, quoted>", "severity": "high"|"medium", "proposedIssue": {...} }` — Steps 2–4 (dedup, issue-raising, reconciliation) consume this identically to C1–C12, no special-casing needed anywhere downstream. Severity: **high** when the spec is `implemented` (shipped behaviour contradicting its record), **medium** when `approved` (drift caught before the status flipped).

**File an issue only — no embedded judgment on which side is "right."** A human decides whether to fix the code or update the spec; this check's job is to surface that the two have diverged, not to adjudicate which one should change. This mirrors every other check's advisory-only posture (see Safety, below) — C13 is not a CI gate, and finding drift here is never grounds for one.

**Weight:** `×2` in the composite score (spine-adjacent, alongside C1/C5 — see `references/check-mechanisms.md` for the full weights list). **Cross-reference:** `/sgd:drift-hillclimb` restates these weights in its own Step 2 ranking — any change here must update that skill in the same PR.
